# 线站值班职责的代理授权

跨站代班、查阅和交接记录的许可来源的本地资料以 JSON 保存，全部身份、系统与输入均为合成。`replay.py` 只回放各参与方提供的事实；`authz/` 在同一组只读资料上实现代理授权核对服务。

需要 Python 3.11。运行 `python3 -m unittest discover -s tests -v` 核对项目资料和本地接入。运行 `python3 replay.py` 启动事实回放服务，默认监听 `127.0.0.1:8765`。访问 `/streams` 查看资料名称，`/streams/名称` 读取相应资料，`/timeline?through=60` 读取截至演练时刻 60 收到的事件。也可直接读取 `data/` 中的原始文件。

运行 `python3 authz_run.py` 启动代理授权服务，默认监听 `127.0.0.1:8766`（可用 `--port` 改端口、`--data` 换资料目录）。除 `POST /evaluate` 的不落库试算外，接口均为只读，办理状态由时间线事件回放得到，服务本身不写文件。

## 核对模型

每次业务动作分三段独立核对，任一段不过即拒绝，并在响应的 `checks` 中分别留痕：

1. **本人资格（person）**：使用人以自己身份登录，须在业务线站、该时刻持有有效在岗职责（roles），调离事件截断其当班职责。
2. **代理源头（source）**：来源的使用人须为登录人，站点一致、时刻落在半开区间 `[start, end)` 内；委托链逐段回溯到当班职责的直接委托。上游被冻结则整条下游级联失效；链上任一授予人调离或职责结束，来源失效。再分派来源还要求每段上游带 `subdelegate_read`，且再分派的行为只限 `read`——现场确认（`handover`）不能再分派。
3. **动作权限（action）**：请求行为须在来源的 `duties` 内，并满足办理上下文规则（见下）。

多个有效来源分别支持相应行为、分别列出，服务不做权利拼接。一次交接确认必须由**单条**足以覆盖该责任人的有效来源完成；同一人不得兼作当前交接的发起者与独立确认者。

### 办理规则

- **冻结**：冻结一条来源时，其委托子树一并失效；引用该子树的未完成交接转入 `blocked` 待重新核对，已有其他合法来源支撑的查阅不中断。
- **调离**：当事人在该站的当班职责结束，其授予的来源失效；指向其责任关系的待签交接不得自动改挂到另一条代理关系，须由负责人重新分发（`负责人重发` 是明确的新选择，旧选择在 `history` 留痕），重发后可重新确认，负责人可查到尚缺的确认。
- **跨站移交**：移出站与接收站须分别确认，且接收确认人不得与移出确认人相同——即使同一人在两个站各持有效代理，接收站也须另找有权人员。收物台只在双方就**同一修订**各自独立确认后才判为可接收。内容更正产生新修订，两侧旧确认保留留痕但不再有效，须重新确认。只撤销一侧尚在用的代理时，另一侧已完成的确认仍可用于后续办理，前提是内容与责任人未变。

## 授权服务接口

| 方法与路径 | 说明 |
| --- | --- |
| `GET /replay` 或 `/replay?through=60` | 回放全部（或截至某时刻的）业务事件，逐事件给出三段核对决策 |
| `GET /effective?person=s8&site=east&at=30` | 某人在某站某时刻仍可使用的代班权限，按来源分别列出 |
| `GET /survivors?grant=g21&at=41` | 某条委托收回后被级联失效的来源，以及各站仍可使用的代班权限 |
| `GET /missing?at=67` | 签字前可查的尚缺确认清单（含被阻塞交接的原因） |
| `GET /receivable?site=west&at=40` | 收物台核对真正可接收的移交及两侧确认明细 |
| `GET /handovers/H8?at=62`、`GET /transfers/T11?at=40` | 单个交接/移交在该时刻的完整办理状态与留痕 |
| `POST /evaluate` | 以登录人身份试算一次动作，不落库；请求体见下 |

`/evaluate` 请求体：查阅 `{"at":38,"actor":"s9","site":"east","duty":"read","grant":"g23"}`；交接确认 `{"at":47,"actor":"s8","grant":"g22","handover_id":"H8"}`；移交确认 `{"at":39,"actor":"s8","grant":"g26","transfer_id":"T11","side":"destination","revision":1}`（`side` 取 `origin`/`destination`）。拒绝时响应带机器可读原因码（如 `principal_mismatch`、`independence_violation`、`grant_frozen`、`revision_mismatch`）与中文说明。

## 资料约定

roles 来自排班部门，duty 是人员受管理的职责。grants 是初始委托记录，parent 为空表示由当班职责直接委托，否则指明许可来自哪条上游代理。时间按 starts/start 含端点及 ends/end 不含端点解释。handover 是工作台已有的待签交接记录，principal 为待签所代表的责任人，grant 为提出办理时选用的代理来源。引用的人物编号由统一身份名录分配。
timeline 中冻结事件指明一条代理来源。负责人重发是明确的新交接选择，不是撤销结果的副本。调离信息由排班部门提供。transfers 给出跨站仪表移交单、两站责任人与交接内容修订，timeline 的移出和接收确认引用相应修订；内容更正事件（`交接修订`）会产生新修订并要求两站重新确认。
